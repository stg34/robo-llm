# body/ — прошивка Arduino

Прошивка борта робота: моторы, датчики, телеметрия и приём команд по радиоканалу.
Архитектурные решения и протокол — см. также `src/docs/protocol.md`.

## Платформа

- **Плата:** Arduino Leonardo/Micro.
- **`Serial1`** — радиомодуль (57600 бод): телеметрия TX + приём команд RX.
- **`Serial`** (USB) — только отладочный вывод (`INIT`, `TURN`, `MOVE`, `BIAS_ADJ`...).
- Сборка: открыть `body.ino` в Arduino IDE. Библиотеки — `libraries/*.zip` (TroykaIMU, L3G4200D, Servo).

**Распиновка** (сводка в шапке `body.ino`):

| Узел | Пины |
|------|------|
| Мотор L | DIR=4, PWM=5, ток=A1 |
| Мотор R | DIR=7, PWM=6, ток=A0 |
| Вольтметр | A3 (делитель, `DIVIDER_RATIO=5.8`) |
| Компас + гироскоп | I2C (Troyka IMU) |
| Дальномер | I2C slave 0x08 (отдельный Pro Micro, `lidar_slave.ino`) |
| Серво-курок | 9 (Timer1) |
| Биппер | 8 (активный пьезо) |
| LED красный / синий | 10 / 11 |

## Структура файлов

Каждая подсистема — пара `.h` (интерфейс + константы) + `.ino` (реализация).

| Файл | Назначение |
|------|-----------|
| `body.ino` | Точка входа: `GlobalState`, `setup()`, `loop()` (планировщик), `serialEvent1()` |
| `protocol.h` | **Константы протокола и тайминга**: бод, периоды, состояния FSM, коды ответов, пины |
| `uplink.{h,ino}` | Связь по `Serial1`: парсер команд (FSM), сборка телеметрии, `D:`-ответы |
| `motion_controller.{h,ino}` | PD-регулятор поворотов (по гиро) и проездов (по дальномеру), 50/100 Гц |
| `motor_driver.{h,ino}` | Один мотор: DIR+PWM, мягкий старт (`set_speed`) или прямое (`set_speed_direct`), ток с АЦП |
| `gyroscope.{h,ino}` | L3G4200D: чтение gyro_z (°/с), калибровка bias, тёплая коррекция `adjust_bias` |
| `magnetometer.{h,ino}` | Troyka Compass: GX/GY в миллигауссах (heading считает хост) |
| `voltmeter.{h,ino}` | Напряжение АКБ через делитель на A3 |
| `rangefinder.{h,ino}` | Опрос лидара-slave по I2C, дальность в мм |
| `servo_gun.{h,ino}` | Неблокирующий цикл выстрела (IDLE→FIRING→RELEASING), калибровочный `set_pos` |

## Архитектура runtime

**`GlobalState`** (`body.ino`) — владеет указателями на все подсистемы; единственный
глобальный объект `robot`. Создаётся в `setup()`.

**`loop()`** — кооперативный планировщик, период `LOOP_DELAY_MS=10` → **100 Гц**:
- каждый цикл: гиро (для PD), разбор pending-команд, тик `MotionController` и серво;
- ручные `L/R` применяются к моторам **только когда `motion->is_idle()`** (контроллер движения имеет эксклюзив);
- дальномер — каждый 5-й цикл (`RANGEFINDER_EVERY_N`) → 20 Гц;
- телеметрия + медленные датчики — каждый 10-й (`TELEMETRY_EVERY_N`) → 10 Гц.

Все подсистемы **неблокирующие**, на `millis()`. Никаких `delay()` внутри логики
(единственный `delay` — задающий период в начале `loop()`).

**Приём команд:** `serialEvent1()` → `Uplink::rx_event()` дренирует буфер и крутит FSM
посимвольно. Полная команда выставляет `*_pending`-флаг; `loop()` опрашивает флаги,
диспатчит в подсистему и сбрасывает. В каждый момент хранится один pending каждого типа.

## Протокол (актуальное состояние)

Спецификация: `docs/protocol.md`. Кадр телеметрии реально содержит **больше полей**, чем
базовый v2 в корневом `CLAUDE.md`:

```
---
SQ LS RS LC RC GX GY V RF GZ LR LB
***
```
`GZ` — gyro_z °/с (float), `LR`/`LB` — состояние LED (0/1). Хостовый парсер
(`pilot/serial_link.py::_parse_frame`) разбирает все поля, отсутствующие — игнорирует.

**Команды хост→борт** (все фикс-ширины, заканчиваются `\n`):
`L/R<DDD>` моторы (128=стоп), `P<DDD>` биппер, `S<DDD>` серво-позиция,
`T±DDDD` поворот°, `M±DDDD` проезд мм, `G±DDDD` коррекция bias (десятые °/с),
`F` выстрел, `E<R><B>` оба LED атомарно.

**Ответы борт→хост** (вне кадра): `D:<code>:<angle>` — `OK/TO/ST/OB/JM`,
angle = накопленный гиро-угол поворота (для проездов 0.0).

## Подводные камни (читать перед правкой)

- **Биппер — активный пьезо:** только `digitalWrite(HIGH/LOW)`, **не `tone()`** (конфликт таймеров с PWM).
  Реализован неблокирующе через `beep_end_ms`.
- **Таймеры:** моторы PWM на пинах 5/6 = Timer3/Timer4; серво (Servo.h) на пине 9 = Timer1 → конфликта нет.
- **Знак гироскопа:** `GYRO_SIGN=-1` в `motion_controller.h`, выверен эмпирически. Не трогать без проверки на железе.
- **Тёплая калибровка гиро:** `setup()` калибрует на холодную (`calibrate(30)`, ~500мс);
  Python досылает `G±DDDD` после прогрева — компенсация теплового дрейфа bias.
- **Проезд (`M`)** — обратная связь по дальномеру + Alpha-Beta фильтр скорости + гиро-коррекция курса.
  Отказ `OB`, если перед стартом дистанция < `MOVE_MIN_RANGE` (200мм). Тюнинг-константы — в `.h`.
- **PD-константы поворота/проезда** вынесены в `motion_controller.h` (`TURN_*`, `MOVE_*`, `AB_*`) — настраиваются эмпирически.
- Изменил тайминг/поля кадра — синхронизируй `pilot/serial_link.py` и `docs/protocol.md`.

## Тестовый режим

`#define GANGLION_TEST_MODE` (закомментирован в `body.ino`) — без датчиков/моторов:
работает только `Uplink` на `Serial1`, шлёт фиктивную телеметрию и эхо разобранных команд.
Позволяет гонять хостовый парсер без железа.

## Ответная часть на хосте — `pilot/`

Зеркало протокола: **`pilot/serial_link.py`** (`SerialLink`).
- Фоновый поток читает `Serial1`, парсит кадры → иммутабельный `TelemetryFrame` (`telemetry.py`).
- Отправка: `set_motors`, `beep`, `send_turn`/`send_move` + `wait_for_done`, `send_fire`,
  `send_servo_pos`, `set_leds`, `send_gyro_bias_correction`.
- `calibrate_gyro()` — измеряет bias на хосте (медиана), затем `send_gyro_bias_correction` досылает
  поправку в прошивку (`G`-команда → `GyroSensor::adjust_bias`).
- Медианный фильтр gyro_z (окно 3) гасит I2C-всплески; вычитает свой `_gyro_bias`.
- Команды `D:` ловятся вне кадра и разблокируют `wait_for_done`.

Выше по стеку: `navigator.py` (turn/move/stop поверх SerialLink), `compass.py` (GX/GY→heading),
`brain.py` (AI-цикл). Подробности — корневой `CLAUDE.md`.
